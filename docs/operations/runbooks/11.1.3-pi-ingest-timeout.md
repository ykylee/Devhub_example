# §11.1.3 Pi Ingest Pipeline Timeout / Degraded

> umbrella doc §11.1.3 — Pi subprocess hang (>30초 timeout) or Pi LLM 출력 invalid

- **Severity**: warning (Pi vendor outage 시 critical)
- **Detection**:
  - `raw_records.ingest_locked_until > NOW()` → lock 풀리지 않은 raw
  - degraded flag (`x_devhub_degraded_fields`) 증가
  - §10.3 fallback 발동 (Pi LLM unreachable → rule-based fallback)
  - §11.3 metric 4 (Pi ingest success rate) < 95% (warning) / < 80% (critical)
- **Triage**:
  1. Pi subprocess 상태 확인 (`pgrep`, `top`)
  2. Pi LLM 출력 샘플 확인 (마지막 5개 ingest 의 output)
  3. Pi vendor 의 status page 확인 (`pi.dev` / vendor API)
- **Mitigation**:
  - Pi subprocess timeout → `ingest_locked_until = NULL` (수동, 다음 cycle 에서 retry)
  - Pi LLM invalid → §10.3 fallback 으로 rule-based normalize 자동 전환
  - Pi vendor outage → §10.3 fallback 으로 rule-based 일시 운영
- **Recovery**:
  - Pi 복귀 시 자동 detect → fallback 해제
  - rule-based 로 이미 처리된 raw 는 Pi 로 재처리 옵션 (M-v0.2.3+)
- **MTTR target**: 30분 (warning) / 2시간 (critical)
- **Related**: §10.3 (Pi ingest pipeline), §3.7.6.1 (partial failure), §3.5.7.5 (M1~M5 metrics)
- **M-v0.2.0 PoC note**: Pi 미설치. M-v0.2.3+ 시점 활성화.
