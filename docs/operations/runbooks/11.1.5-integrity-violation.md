# §11.1.5 Integrity Violation

> umbrella doc §11.1.5 — §4.7 raw 정합성 검증 의 sha256 hash mismatch

- **Severity**: high (단발) / critical (반복)
- **Detection**:
  - `audit.raw.integrity_violation` event (severity: high)
  - `GET /api/v0-2/raw/{type}/{name}` 응답의 `E_INTERNAL` ("raw.integrity_violation")
  - §11.3 metric 3 (integrity violation rate) > 0.01% (warning) / > 0.1% (critical)
- **Triage**:
  1. source_timestamp vs received_at 비교 (외부 시스템 응답 시점 vs DB write 시점)
  2. fs vs sqlite 의 mtime 비교 (file mode 의 경우)
  3. raw_records 의 sha256 vs file 재계산 비교 (db mode 의 경우)
- **Mitigation**:
  - source plugin 의 sync 재실행
    ```bash
    curl -X POST -H "X-DevHub-User-Context: ..." \
      http://localhost:8000/api/v0-2/ingest/homelab_mock/sync
    ```
  - DB mode 의 경우: source plugin 의 fetch 결과로 `UPDATE raw_records SET data_json_encrypted = ?, data_json_hash_sha256 = ? WHERE id = ?`
- **Recovery**:
  - hash 일치 후 audit log success
  - integrity violation alert 해제
  - 1시간 이내 미복구 시 critical alert
- **MTTR target**: 30분
- **Related**: §4.7 (raw 정합성), §11.2 (backup/DR)
- **M-v0.2.0 PoC note**: file mode only. M-v0.2.3+ production 시 db mode 추가.
