# §11.1.4 Retention Cron 실패

> umbrella doc §11.1.4 — 매일 03:00 UTC cron 의 retention_days 초과 raw 자동 삭제 실패

- **Severity**: warning (storage quota 90% 초과 시 critical)
- **Detection**:
  - cron audit log 미기록 (cron 자체 fail)
  - storage quota 90% 임계 초과 alert (§11.3 monitoring)
  - §11.3 metric 1 (raw count) 증가 추세 (retention 미작동 시)
- **Triage**:
  1. cron daemon 상태 확인 (`crontab -l`, `systemctl status cron`)
  2. retention_days 컬럼 / WHERE 조건 검증
  3. raw_records 의 `received_at + retention_days < NOW()` row count
- **Mitigation**:
  - cron daemon 재시작
  - retention_days 값 잘못 설정된 raw 수동 삭제
    ```sql
    DELETE FROM raw_records WHERE received_at + retention_days < NOW()
    ```
- **Recovery**:
  - cron 정상 작동 시 다음 03:00 UTC 부터 자동 retention 재개
  - storage quota 90% 이하 회복 시 alert 해제
- **MTTR target**: 1시간
- **Related**: §10.6 (운영 가이드 per storage mode)
- **M-v0.2.0 PoC note**: cron 미설정. 운영자가 수동 실행. M-v0.2.3+ production 시 cron 등록.
