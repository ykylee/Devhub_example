Overview

과제 개요와 현재 목표

프로젝트 목적

역할별 운영 대시보드와 조직·과제·외부 연동 기능을 하나의 플랫폼으로 묶어 개발 및 딜리버리 통합 가시성을 제공합니다.

핵심 사용자군

역할 체계는 developer, team_manager, system_admin 3축이며, 온보딩 및 승인 프로세스를 거쳐 권한이 정비됩니다.

중간 보고 관점

가상 계획 수립보다, 실제 컴파일·빌드·테스트가 완료되어 현재 정상 동작하는 기능과 SDLC 추적성 자산을 투명하게 증명합니다.

핵심 비즈니스 도메인 범위

Auth / OIDC (Keycloak) Organization / RBAC Application / Project Repository / SCM (Git) DREQ (Intake Flow) External Integration Audit Log / CI Visibility

인증부터 개발 의뢰(DREQ), CI 상태 추적, 외부 프로바이더 연동까지 유기적으로 연결된 플랫폼입니다.

Concept

개발 컨셉과 단계별 확장

지속 가능한 컴포넌트 연결

역할별 전용 랜딩 페이지를 기반으로 최적화된 UX를 설계하고, 이들을 업무 도메인과 엮었습니다.

  • 업무 체인 연결: Application ➜ Project ➜ Repository ➜ DREQ
  • 인프라 정합: OIDC 인증, 단일 포트 프록시 라우팅, DB 마이그레이션 자동화

추적 지향적(Traceability) 개발

단순 구현을 넘어, 아키텍처 및 요구사항과 코드 구현의 연결고리를 견고하게 유지합니다.

  • 모든 신규 피처 마다 REQ, ADR, API, TEST 문서를 병행 정비
  • AI Agent가 각자의 책임 영역(Infra/Test/Front/Back)에 특화하여 병합 충돌 최소화

Implementation

현재 구현 범위 상세 요약

인증 및 권한 (OIDC) Keycloak 기반 SSO 토큰 검증, JWT/JWKS 파싱 라이브러리 탑재, 비인가 사용자의 Onboarding 리디렉션 흐름 완비.
조직 및 계정 관리 부서 생성·수정·삭제 API 및 계정 매칭, 관리자 권한 정책 편집 대시보드, 시스템 감사 로그 적재 및 연동.
Application / Project 다중 프로젝트 스페이스, 멤버 초대 및 관리자 위임, Git 리포지토리와의 Soft-link 관계 바인딩 API 완비.
Repository / SCM 리포지토리 Draft/Publish 라이프사이클 관리, 브랜치별 활성도 시각화 카드, 대화형 Catalog Drilldown 제공.
DREQ (의뢰 관리) Intake 토큰 보안 발급 및 만료 처리, 타 플랫폼 외부 연동 Promote 트리거, 접수 알림 및 대시보드 표시.
External Integration Provider별 Credential 암호화 및 바인딩, Topology V2 네트워크 구조 시각화, 연동 상태 헬스체크 및 동기화 스케줄러.
