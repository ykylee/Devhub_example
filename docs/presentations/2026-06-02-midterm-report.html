Overview

과제 개요와 현재 목표

프로젝트 목적

역할별 기본 진입 우선순위 대시보드와 조직/과제/외부 연동 운영 기능을 통합하는 관리 플랫폼을 구축한다.

핵심 사용자군

Developer, Team Manager, PMO Manager, System Admin 각각의 업무 흐름을 하나의 서비스 안에서 연결한다.

중간 보고 관점

미래 계획보다 현재 실제 동작 범위, 문서화 수준, 테스트 충실도, 협업 구조를 중심으로 보고한다.

핵심 도메인

Auth / OIDC Organization / RBAC Application / Project Repository / SCM DREQ External Integration Audit / CI Visibility

DevHub는 단순 화면 프로토타입이 아니라 인증, 조직, 프로젝트, 외부 연동, 개발 의뢰 흐름까지 연결된 운영형 플랫폼으로 진화했다.

Concept

개발 컨셉과 출발점

초기 컨셉

  • 역할 기반 기본 landing 과 작업 대시보드를 중심으로 사용자 경험을 설계
  • 실제 업무 객체를 Application → Project → Repository 및 DREQ 흐름으로 모델링
  • 인증, 권한, 외부 시스템 연동을 분리된 기능이 아니라 운영 체계로 통합

진행 방식

  • 기능 개발과 문서 정합 작업을 병행
  • 도메인 문서, ADR, API 문서, traceability report 를 같이 유지
  • AI agent 를 역할별 워커로 배치해 backend, infra, frontend, test 축을 병렬 진행

Traceability

SDLC 추적성과 연결 관계

레이어 대표 ID / 자산 현재 보고 포인트
Requirement REQ-FR / REQ-NFR 도메인 요구사항이 traceability matrix 와 연결되어 이후 설계/구현으로 추적 가능
Architecture ARCH / ADR Keycloak-only, single-port, code taxonomy 등 구조 결정이 ADR 및 governance 문서에 남아 있음
API API-* 계약 문서와 실제 route/handler/test 가 매핑됨
Implementation IMPL-* PR 단위로 영향 지점과 구현 책임이 명시됨
Testing UT / TC 단위테스트와 E2E 시나리오가 matrix 및 test_cases 문서와 연결됨

중간 보고에서 중요한 것은 문서가 “존재한다”가 아니라, 문서들이 서로 링크되고 실제 코드와 테스트로 이어지는 관리 체계가 이미 작동 중이라는 점이다.
