## 2. 4가지 기능 overview

### 2.1 FR-1 Ingest (수집)

**목적**: 외부 시스템 (Gitea 4 sub-plugin + M-v0.2.2+ homelab + M-v0.2.3+ metrics + M-v0.2.3+ hrdb) 의 raw 데이터를 봉투 암호화 후 `var/raw/` (file mode) 또는 DB `raw` table (db mode) 에 저장. M-v0.2.0 PoC = Gitea 4 sub-plugin 만 (homelab / metrics / hrdb 제외).

**6 endpoint** (umbrella doc §3.1 정합):
- `POST /api/v0-2/ingest/{source}/sync` — sync trigger
- `GET /api/v0-2/ingest/{source}/status` — sync 상태 조회
- `POST /api/v0-2/raw` — 1차 raw 등록 (manual)
- `GET /api/v0-2/raw/{type}/{name}` — 1차 raw 조회
- `GET /api/v0-2/raw?source=...&since=...` — 1차 raw list (filter)
- `DELETE /api/v0-2/raw/{id}` — 1차 raw 삭제 (impact analysis)

**cell 적용 (28 PoC cell)**: source 4종 × type 7종 (decision 제외) = 28 cell. source axis 가 Ingest 기능의 trigger 축. cell 마다 primary 기능 = **Ingest** (REQ-D-001/009/017/025 = dataset, REQ-D-002/010/018/026 = metric 등).

**Path Y**: 6 endpoint 중 **`POST /api/v0-2/raw` / `GET /api/v0-2/raw/{type}/{name}` / `GET /api/v0-2/raw?source=...` / `DELETE /api/v0-2/raw/{id}` 4개는 필수** (provenance + visibility + 권한), `POST /api/v0-2/ingest/{source}/sync` / `GET /api/v0-2/ingest/{source}/status` 2개는 권장 (system sync, audit attribution).

### 2.2 FR-2 Curate (정리)

**목적**: 1차 raw → OKF concept 변환 (M-v0.2.0~v0.2.2 = rule-based, M-v0.2.3+ = Pi LLM enrich 활성화). manual edit (human curator) + bundle 관리 (CRUD + rebuild).

**5 endpoint** (umbrella doc §3.1 정합):
- `POST /api/v0-2/concepts/{id}/enrich` — raw → OKF concept 변환 trigger
- `PUT /api/v0-2/concepts/{id}` — concept manual edit (human curator)
- `GET /api/v0-2/bundles` — bundle list
- `POST /api/v0-2/bundles` — bundle 생성
- `POST /api/v0-2/bundles/{bundle}/rebuild` — bundle index + cross-link 재생성

**cell 적용 (28 PoC cell)**: primary 기능 = **Curate** 인 cell = REQ-D-008/016/024/032 (decision 4 cell, **M-v0.2.1+ scope**, 본 PoC 제외) + REQ-D-005/013/021/029 (integration 4 cell, umbrella doc §3.2.1.1 의 5 카테고리 대표 concept, source axis 별 1 cell) + REQ-D-007/015/023/031 (reference 4 cell, mirror of external doc). 그 외 16 cell 은 secondary 기능으로 Curate 영향 받음 (cross-link 자동 추출 시).

**Path Y**: 5 endpoint 중 **`PUT /api/v0-2/concepts/{id}` / `POST /api/v0-2/bundles` 2개는 필수** (curation ownership + bundle owner), `POST /api/v0-2/concepts/{id}/enrich` / `POST /api/v0-2/bundles/{bundle}/rebuild` 2개는 권장, `GET /api/v0-2/bundles` 1개는 권장.

### 2.3 FR-3 Query (조회)

**목적**: 자연어 query → context + answer (M-v0.2.0~v0.2.2 = 단순 retrieval + raw context 표시, M-v0.2.3+ = LLM answer 합성) + concept 직접 조회 + full-text search + bundle index + self-contained graph viewer.

**5 endpoint** (umbrella doc §3.1 정합):
- `POST /api/v0-2/query` — 자연어 query → context + answer
- `GET /api/v0-2/concepts/{type}/{name}` — concept 직접 조회
- `GET /api/v0-2/search?q=...` — full-text search
- `GET /api/v0-2/bundles/{bundle}/index.md` — bundle index (progressive disclosure)
- `GET /api/v0-2/bundles/{bundle}/viz.html` — self-contained graph viewer (Cytoscape.js CDN embed)

**cell 적용 (28 PoC cell)**: primary 기능 = **Query** 인 cell = REQ-D-001/009/017/025 (dataset 4 cell) + REQ-D-002/010/018/026 (metric 4 cell) + REQ-D-003/011/019/027 (api_endpoint 4 cell) + REQ-D-004/012/020/028 (runbook 4 cell) + REQ-D-006/014/022/030 (event 4 cell) = 20 cell. 그 외 8 cell (integration/reference × 4) 은 secondary.

**Path Y**: 5 endpoint 중 **`POST /api/v0-2/query` / `GET /api/v0-2/concepts/{type}/{name}` / `GET /api/v0-2/search` 3개는 필수** (user-scoped query + visibility check), `GET /api/v0-2/bundles/{bundle}/index.md` / `GET /api/v0-2/bundles/{bundle}/viz.html` 2개는 권장 (bundle-level visibility check).

### 2.4 FR-4 Graph (cross-link reverse index)

**목적**: cross-link reverse index (in-link list + impact 분석 + 수동 rebuild + Pi LLM link resolve trigger). M-v0.2.0 PoC 부터 능동적 강화 (umbrella doc §3.5.6 정합, 2026-06-18 신규).

**4 endpoint** (umbrella doc §3.1 정합):
- `GET /api/v0-2/graph/reverse/{concept_path}` — reverse link in-link list 조회
- `GET /api/v0-2/graph/impact/{concept_path}` — impact 분석 (in-link + out-link + orphan + rank)
- `POST /api/v0-2/graph/reindex` — reverse index 수동 rebuild (full scan)
- `POST /api/v0-2/concepts/{id}/resolve-links` — Pi LLM link resolve trigger (M-v0.2.3+)

**cell 적용 (32 cell 전체)**: Graph 기능은 **모든 cell 에 cross-cutting 적용** (cross-link graph = 32 cell × N cross-link edge). primary 기능 = **Graph** 인 cell 없음 (모두 secondary).

**Path Y**: 4 endpoint 모두 **권장** (audit attribution + visibility filter). `POST /api/v0-2/concepts/{id}/resolve-links` 의 mode=auto-apply 는 권장 + audit log 필수 (§3.6.6 정공법).

## 4. Endpoint 별 request/response schema (Pydantic v2)

> **공통 envelope**: 모든 endpoint 응답은 `Envelope[T]` (umbrella doc §3.1 / §3.6 정합). `Envelope = {envelope: {...metadata...}, data: T}`.

### 4.0 공통 schema

```python
from pydantic import BaseModel, Field
from typing import Literal, Generic, TypeVar
from datetime import datetime

T = TypeVar("T")

class EnvelopeMeta(BaseModel):
    """공통 envelope metadata (§3.1 + §3.6 정합)."""
    request_id: str = Field(..., description="UUID v4, request correlation")
    timestamp: datetime = Field(..., description="ISO 8601 UTC, server time")
    api_version: Literal["v0-2"] = "v0-2"
    caller_user_id: str | None = Field(None, description="X-DevHub-User-Context.user_id (Path Y)")
    path_y_validated: bool = Field(..., description="Path Y header format 검증 결과")

class Envelope(BaseModel, Generic[T]):
    """공통 envelope wrapper. 모든 endpoint 응답의 1차 wrapping."""
    envelope: EnvelopeMeta
    data: T

class PathYUserContext(BaseModel):
    """X-DevHub-User-Context header 의 decoded JSON schema (umbrella doc §3.6.1 정합 — 8 field 1:1).

    Schema fields (per umbrella doc §3.6.1 caller-provided user context contract):
    - version: schema version ("v0")
    - user_id: DevHub internal user PK
    - org_id: primary organization
    - org_unit_ids: org_head scope 의 subtree (recursive CTE 결과)
    - project_ids: user 의 project memberships
    - roles: system role + resource role 목록
    - request_id: trace id (envelope trace_id 와 동일값 권장)
    - issued_at: context 생성 시각 (caller 측). 만료 검증은 issued_at + PATH_Y_MAX_AGE_SECONDS 로 별도 수행.
    """
    version: Literal["v0"] = "v0"
    user_id: str
    org_id: str
    org_unit_ids: list[str]
    project_ids: list[str]
    roles: list[str]
    request_id: str
    issued_at: datetime
```

# Path Y header 만료 검증 상수 (umbrella doc §3.6.1 정합 — format 검증 의 issued_at 만료 정책)
PATH_Y_MAX_AGE_SECONDS: int = 300  # 5분 (umbrella doc §3.6.1 "issued_at 만료 (e.g., 5분)")

#### FR-I-001: POST /api/v0-2/ingest/{source}/sync

```python
# request
class IngestSyncRequest(BaseModel):
    """§3.1 Ingest sync trigger. source plugin 의 connect + pull + raw emit 트리거."""
    since: datetime | None = Field(None, description="incremental sync 시작 시점. None = full sync")
    dry_run: bool = Field(False, description="true 시 raw emit 안 함, 연결/credential 만 검증")
    credential: dict | None = Field(None, description="source-specific credential (Gitea: {url, token}). 메모리에서만 사용, 저장 ❌")

# response
class IngestSyncData(BaseModel):
    """sync 결과. M-v0.2.0 PoC = rule-based 만."""
    synced: int = Field(..., description="성공한 raw emit count")
    failed: int = Field(..., description="실패 count")
    raw_ids: list[str] = Field(..., description="emit 된 raw 의 id list (sha256 prefix 7자)")
    next_sync_recommended: datetime | None = Field(None, description="증분 sync 의 다음 권장 시각")
    errors: list[dict] = Field(default_factory=list, description="실패 상세 {raw_path, error_code, error_message}")

# response: Envelope[IngestSyncData]
```

**cell 적용**: REQ-D-001~007 / 009~015 / 017~023 / 025~031 (28 PoC cell, decision 4 cell 제외). 4 source × 7 type = 28.

**Path Y**: 권장 (system sync, audit attribution).

**AC**:
- AC1: `{source} ∈ {gitea_issue, gitea_wiki, gitea_repo_pull, gitea_action}` (M-v0.2.0 PoC) — 4 source 외 source 호출 시 400 `E_VALIDATION`
- AC2: credential 제공 시 source plugin 의 `connect(credential)` 호출 성공 — 실패 시 401 `E_AUTH_FAILED` (source-specific)
- AC3: dry_run=true 시 raw emit 0 + `{synced: 0, failed: 0, raw_ids: []}` 응답
- AC4: sync 완료 시 audit log 에 `ingest.sync` event 기록 (`var/log/audit.log` JSON Lines, §3.6.6 정공법)

```python
    max_candidates: int = Field(10, ge=1, le=50)

class ResolveLinksCandidate(BaseModel):
    rank: int
    target_concept: str
    confidence: float = Field(..., ge=0.0, le=1.0)
    reasoning: str = Field(..., description="LLM 의 추천 이유 (j2 prompt template, §3.5.7.2)")

class ResolveLinksData(BaseModel):
    concept_id: str
    mode: str
    candidates: list[ResolveLinksCandidate] = Field(..., description="LLM 추천 candidate list")
    applied: bool = Field(False, description="mode=auto-apply + confidence ≥ threshold 시 true")
    applied_at: datetime | None
    error: str | None = None

# response: Envelope[ResolveLinksData]
```

**cell 적용**: 모든 cell (M-v0.2.3+ 부터).

**Path Y**: 권장 + **audit log 필수** (§3.6.6 정공법). mode=auto-apply 시 audit log 자동 emit.

**AC**:
- AC1: `{id}` = concept_id, 존재 확인 — 미존재 시 404 `E_NOT_FOUND`
- AC2: mode=dry-run 시 LLM 추천만, link add ❌
- AC3: mode=confirm 시 operator 가 selected_rank 선택 후 link add 1건 (1번 호출)
- AC4: mode=auto-apply 시 confidence ≥ threshold 인 candidate 모두 link add + audit log + §3.5.8.2 rollback trigger 활성화

### 5.2 Path Y format 검증 (5 field 매핑)

```python
# §3.6.1 정합: X-DevHub-User-Context header 의 decoded JSON 검증
class PathYValidator:
    def validate(self, header_value: str) -> PathYUserContext:
        # 1. base64url decode
        decoded = base64url_decode(header_value)
        # 2. JSON parse
        data = json.loads(decoded)
        # 3. schema check (PathYUserContext 모델 — 8 field 1:1 정합, version/user_id/org_id 필수 §3.6.1)
        ctx = PathYUserContext.model_validate(data)
        # 4. 만료시간 check (issued_at + PATH_Y_MAX_AGE_SECONDS, §3.6.1 format 검증)
        age = datetime.utcnow() - ctx.issued_at
        if age > timedelta(seconds=PATH_Y_MAX_AGE_SECONDS):
            raise EValidation("X-DevHub-User-Context expired")
        return ctx

    def map_to_governance_fields(self, ctx: PathYUserContext) -> GovernanceFields:
        """caller context → 5 governance field 매핑 (§3.6.4 정합).

        Note: PathYUserContext 의 roles 필드는 5 governance field 중 visibility inference 만 사용.
        """
        return GovernanceFields(
            x_devhub_owner_org_id=ctx.org_id,
            x_devhub_owner_user_id=ctx.user_id,
            x_devhub_owner_org_unit_ids=ctx.org_unit_ids,
            x_devhub_owner_project_ids=ctx.project_ids,
            x_devhub_visibility=self._infer_visibility(ctx),
        )

    def _infer_visibility(self, ctx: PathYUserContext) -> Literal["org", "personal", "project", "public"]:
        # 4-tier scope priority (org > personal > project > public, §3.6.3)
        if "system_admin" in ctx.roles:
            return "org"
        if ctx.project_ids:
            return "project"
        if ctx.org_unit_ids:
            return "org"
        return "public"
```

### 5.3 Query scope priority 4-tier (org > personal > project > public)

> **umbrella doc §3.6.3 정합**: query 시 caller 의 scope 와 concept 의 visibility 매칭 시 우선순위 = org > personal > project > public. 즉, caller 가 org unit 에 속하면 org visibility concept 만 visible, project 만 있으면 project visibility concept 만 visible, 둘 다 없으면 public.

| caller scope | concept visibility 매칭 | visible? |
| --- | --- | --- |
| caller.org_unit_ids ⊇ concept.owner_org_unit_ids | `org` | ✅ |
| caller.user_id == concept.owner_user_id | `personal` | ✅ |
| caller.project_ids ∩ concept.owner_project_ids | `project` | ✅ |
| 모두 불일치 | `public` | ✅ |
| caller.system_admin role 보유 | 모든 visibility | ✅ |
