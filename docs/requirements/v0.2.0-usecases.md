## 0. 사용 가이드

본 문서는 SDLC 요구사항 단계의 §4 = **유스케이스 (UC)**. §1 + §2 + §3 의 후속:

1. **§1 도메인 분류** (직전 turn) — source × type 매트릭스 + representative concept + REQ-ID
2. **§2 기능 요구사항 (FR)** (직전 turn) — 4가지 기능 (Ingest / Curate / Query / Graph) × cell 매핑 + endpoint schema
3. **§3 비기능 요구사항 (NFR)** (직전 turn) — performance / security / availability / observability × 32 cell + 28 metrics + RTO/RPO
4. **§4 유스케이스 (UC)** (본 문서) — 4 actor × per-actor 시나리오 + cell × usecase + endpoint × usecase
5. **§5 추적성 매트릭스** (후속 turn) — REQ + FR + NFR + UC → IMPL → UT → TC

본 turn 작성 = §4 (UC). §5 는 후속 turn.

## 2. 4 Actor 정의

### 2.1 Actor-1 End-User (visitor + AI agent)

**정의**: knowledge consumer (read only, GET endpoint). §12.3 의 visitor role (모든 인증된 user, Path Y caller-provided user context 정합).

**primary use case**:
- **UC-EU-001**: 자연어 query 로 knowledge 검색 (`POST /api/v0-2/query`)
- **UC-EU-002**: 특정 concept 직접 조회 (`GET /api/v0-2/concepts/{type}/{name}`)
- **UC-EU-003**: full-text search (`GET /api/v0-2/search?q=...`)
- **UC-EU-004**: bundle index 확인 (`GET /api/v0-2/bundles/{bundle}/index.md`)
- **UC-EU-005**: bundle viz.html 자가 viewer 조회 (`GET /api/v0-2/bundles/{bundle}/viz.html`)
- **UC-EU-006**: AI agent 호출 (End-User via AI agent, LLM 합성 query answer, M-v0.2.3+)

**권한**:
- `x_devhub_visibility = public` 인 concept + bundle 만 조회 가능
- Path Y caller-provided user context 의 4-tier scope priority (§3.6.3) 적용
- Audit log: `audit.user_login` (login) + `audit.concept_access` (조회) + `audit.query` (자연어 query) + `audit.user_login_count` per user (metric 16, §3.6.6.3)

**actor role**:
- 4 curator_type 중 해당 없음 (read only)
- §12.3 visitor frontend UI (concept list + detail read only)

### 2.2 Actor-2 Curator (human-self-user, human-org-head, llm-system_admin)

**정의**: human 작성자 (End-User self-author or org head) + M-v0.2.3+ LLM curator (AI agent curator). §3.6.2 의 3 curator_type (human-self-user / human-org-head / llm-system_admin).

**primary use case**:
- **UC-CU-001**: human concept manual edit (`PUT /api/v0-2/concepts/{id}`, 5 curator_type 권한 check, §3.6.2)
- **UC-CU-002**: rule-based 자동 curation (`POST /api/v0-2/concepts/{id}/enrich`, curator=rule-based, M-v0.2.0 PoC)
- **UC-CU-003**: LLM curation (Pi LLM enrich, `POST /api/v0-2/concepts/{id}/enrich` enricher=pi-llm, M-v0.2.3+)
- **UC-CU-004**: Pi LLM operator confirm workflow (`POST /api/v0-2/concepts/{id}/resolve-links?mode=confirm&selected_rank=N`, 3 mode 정공법 §3.5.7)
- **UC-CU-005**: bundle 생성 (`POST /api/v0-2/bundles`, owner_org_id 설정, §2 FR FR-C-004)

**actor role**:
- 3 curator_type (human-self-user / human-org-head / llm-system_admin)

#### UC-EU-001: 자연어 query 로 knowledge 검색

```yaml
# §2 FR FR-Q-001 (POST /api/v0-2/query)
actor: End-User
precondition:
  - Path Y caller-provided user context 정상 (X-DevHub-User-Context header, 8 field)

  - §3 NFR NFR-P-002: query p95 < 500ms (PoC) / < 200ms (M-v0.2.1+) / < 5s (M-v0.2.3+ LLM 합성)
```
